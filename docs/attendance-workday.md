# 勤務日と打刻日時（Issue #1）

- 勤務日は日本時間の04:00以上、翌04:00未満。午前0〜3時台の出勤は前日の勤務日になります。
- 退勤は現在の勤務日ではなく、本人の未退勤レコードに記録します。勤務日と出勤日時は変更しません。
- 既存データの移行・再計算は行いません。適用前の未退勤レコードもそのまま退勤できます。
- 未退勤レコードがあれば、新しい出勤をAPIで拒否します。過去に複数の未退勤レコードができていた場合は、古いものから解消します。
- 前の勤務日の未退勤レコードをホーム画面で案内します。案内は、打刻を忘れていた場合も先に「退勤を記録」を押すよう求めます。退勤を記録すると、その勤務の編集欄を開くリンクを表示します。利用者はそこで実際の退勤日時に直せます。
- 月別記録で退勤日時を入力しても、出勤を打刻した勤務は終わりません。勤務を終えるのは退勤の打刻だけです（#20）。編集の後に退勤を打刻すると、入力した退勤日時は打刻した時刻で上書きされます。
- ホーム画面は表示・フォーカス復帰時と表示中の30秒ごとに更新します。打刻時はサーバーの現在時刻で判定します。
- 編集は実際の日本時間の日付と時刻を指定します。勤務日は固定で、未変更の日時の秒精度は維持します。
- 月別画面・PDFは保存済みの勤務日で抽出し、実際の出退勤の日付・時刻を併記します。
- 午前4時ちょうどのメール・プッシュ通知、自動の退勤補完は行いません。

## ローカルでの確認

`npm run test:local` で単体テスト、ビルド、ローカルWorker/D1でのAPI検証を実行します。
ブラウザでの確認では、既存のローカル利用者で次を確認してください（本番データにテスト打刻しないこと）。

1. 前の勤務日の未退勤があるとホームに案内が出る。案内には月別記録へのリンクがない。
2. 「退勤を記録」を押すと案内が消え、退勤を記録したことと、退勤日時を直すリンクが表示される。
3. そのリンクで対象の月・レコードの編集欄が開く。
4. 翌日以降の退勤日時を保存でき、勤務日は変わらない。
5. ホームに戻ると、当日の新たな出勤が可能になっている。
6. PDFと月別画面の勤務日・実際の出退勤日時が一致する。

本番確認はPRのレビュー・マージ後に別途行い、Issueに結果を記録します。
